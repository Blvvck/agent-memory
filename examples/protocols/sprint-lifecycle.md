# Optional Sprint Lifecycle

Use this procedure only when the project has chosen the optional `work/SPRINT.md` and backlog workflow. It does not make sprints or scoring mandatory for Agent Memory.

## Plan

1. Confirm the sprint goal and the people available to do the work.
2. Select stories from the backlog that support that goal and have clear acceptance criteria.
3. Check estimates, dependencies, integration work, verification, and risks before committing to the scope.
4. Record the selected stories, owners, status, and completion conditions in `work/SPRINT.md`.

## Run

1. Keep story status current as work starts, becomes blocked, enters review, and completes.
2. Share blockers early and identify who can resolve them.
3. Integrate and verify work as it lands; do not defer all integration to sprint end.
4. Record meaningful decisions and outcomes in project `ACTIVITY.md` and agent memory using the required [agent-log protocol](../../protocols/agent-log.md).

## Close

1. Verify each story against its observable acceptance criteria.
2. Mark incomplete work clearly and return it to the backlog with its remaining steps and dependencies.
3. Record the outcome, unresolved risks, and useful lessons in the project activity log through the required [agent-log protocol](../../protocols/agent-log.md).
4. If the project opted into `LEADERBOARD.md`, update it according to the scoring rules agreed by the team. Do not add scoring by default.
5. Use the results to set the next sprint goal or return to normal task planning.
