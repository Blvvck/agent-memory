# Optional Shared File Updates

Use this procedure when a project or team maintains shared planning, discussion, or score files. These files are optional; agree which ones to use before assigning owners or update rules.

## Agree on ownership

For each enabled file, decide who may update it and who is responsible for keeping it current. Ownership can belong to a person, a role, or the whole team. Do not assume a role or owner that the team has not chosen.

| File, if enabled | Update when |
|---|---|
| Global or project `ACTIVITY.md` | Meaningful work in that scope is completed or a significant outcome is verified |
| `NOTIFICATIONS.md` | Someone needs to respond, make a decision, or remove a blocker; close or mark the request when resolved |
| Project `IDEAS.md` | A useful project idea arises outside the current task |
| `work/BACKLOG.md` | Unscheduled work is added, clarified, prioritized, or completed |
| `work/SPRINT.md` | Sprint scope, ownership, status, or completion changes |
| `work/features/` | A feature specification or breakdown is created or materially revised |
| `LOUNGE.md` | The team chooses to share a discussion, announcement, or celebration |
| `LEADERBOARD.md` | The team has agreed on scoring and a score or period is finalized |

Follow the required [agent-log procedure](../../protocols/agent-log.md) for protected memory, activity, and notification files. This guide does not replace its entry format, trace, or writer requirements.

## Keep each file useful

- Record a fact or status in one authoritative place, then link to it from other files when needed.
- Keep activity logs for completed work and outcomes; use notifications for requests that need action.
- Update status where the team tracks that status instead of leaving contradictory copies elsewhere.
- Remove or mark resolved requests according to the team's chosen convention.
- Agree on any scoring definitions before recording leaderboard results. Do not introduce scores or rankings by default.
- If ownership or update timing is unclear, agree on it with the people maintaining the files rather than silently inventing a rule.
