# Optional Team Coordination

Use these procedures when people choose to coordinate work across multiple agents. They supplement the required Agent Memory protocols; core memory, activity, project setup, and named-agent wake do not depend on them.

## Shared updates

Use the global `TASKS.md` only for shared follow-ups that do not belong to one project's work plan. Use project `LOUNGE.md` for discussion and threads when the project has opted into that file. Keep work outcomes in project `ACTIVITY.md`; discussion and scoreboards do not replace the project work log.

## Handoffs

When handing work to another agent, include the task and expected outcome, relevant decisions, files changed, verification already performed, remaining work, and blockers. Point to the appropriate memory or activity entry rather than copying a long conversation. For a named agent with a body, follow the required [subagent wake protocol](../../protocols/subagent-wake.md); record completed work through the required [agent-log protocol](../../protocols/agent-log.md).

## Optional coordination files

Add only the files people agree to maintain:

- Global `LOUNGE.md`, `TASKS.md`, and `LEADERBOARD.md` for cross-project discussion, shared follow-ups, and aggregate scores.
- Project `work/SPRINT.md`, `work/BACKLOG.md`, and `work/features/` for structured planning.
- Project `LOUNGE.md` and `LEADERBOARD.md` for project discussion and scores.

Agree on ownership, update cadence, and what a score means before using a leaderboard. See [file-updates.md](file-updates.md) for shared-file ownership, [standup.md](standup.md) for status summaries, and [project-planning.md](project-planning.md) and [sprint-lifecycle.md](sprint-lifecycle.md) for optional planning workflows.
