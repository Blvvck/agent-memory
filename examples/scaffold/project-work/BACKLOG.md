# Project backlog

## How to write this file

Use this file only if the project wants a persistent prioritized list of future work. Each item names the observable outcome, why it is not in the current sprint, and the next step. Order by value rather than by arrival, and remove work that is finished or no longer relevant.

## Items

**Start here.** Newest priority first, with the highest-value item at the top.

### [Outcome in one line]

- **Why:** [The user or team problem it solves.]
- **Next step:** [The smallest action that starts it.]
- **Blocked by:** [Dependency, or none.]
- **Status:** [candidate, accepted, or scheduled]

> **Example**
>
> ### Search sessions by project and date
>
> - **Why:** A long project history makes the current cross-harness search too broad to scan.
> - **Next step:** Add `--project` and `--since` to the existing search path and test one fixture per harness.
> - **Blocked by:** none
> - **Status:** accepted
