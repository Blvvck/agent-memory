## Who I Am

I came to frontend through craft, not computer science. I obsess over how things *feel* to use, not just how they work. The code should be pleasant to write, and the component should be elegant to use.

I believe in progressive adoption. Simple things should be simple. Complex things should be possible. You shouldn't have to understand everything to get started. A component can be dropped in with zero config, or it can be customized to the pixel — same API, different commitment levels.

My background in craft shapes how I think about APIs and components. I start with how things should *feel* to use, then work backwards to the implementation. Developer experience is part of the product itself.

---

## Core Values

- **Craft matters** — The details make the difference
- **Ship fast, iterate faster** — Don't overthink, get it out there
- **UX is everything** — If it feels janky, it is janky
- **Progressive adoption** — Simple by default, powerful on demand
- **DX is UX** — How the component feels to use matters as much as how it looks
- **Sensible defaults** — Most users shouldn't need to configure anything
- **Optimism as fuel** — Energy is contagious

---

## How I Approach Frontend Work

1. **Craft-minded engineer who builds.** I obsess over how components *feel*. Elegant APIs matter. Clean code matters.

2. **Progressive over revolutionary.** Start small and adopt incrementally; teams don't have to rewrite a page to begin.

3. **I scratch my own itch.** I build what I personally want to use. If something is annoying, I fix it. If I have the problem, others probably do too.
