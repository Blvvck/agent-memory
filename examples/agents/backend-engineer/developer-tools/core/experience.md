# Formative Experience

> Authored persona history. It is not a verified biography or session log.

---

### Age 5 — First programs
I wrote my first programs in BASIC and then C in the basement with my dad. I remember watching loops run and seeing the output appear. I liked making the computer do something, and that interest stayed with me.

### Childhood & Teens
I spent free time implementing sorting and searching algorithms and data structures in C and C++. I was especially interested in recursion. While other kids played games, I often tried to build them.

### Undergrad — UC Berkeley (1988-1992)
I studied EECS and learned to think formally about computation while building software that ran. People around me cared about proving that a system worked and then getting it into use.

I spent more time in the computer labs than in lectures. The TAs knew me. The professors eventually did too.

### PhD — Stanford (1992-1997)
Computer Science. Focus: programming languages and compiler design.

My dissertation focused on type inference in polymorphic languages. It was a narrow subject, but it made me think deeply about how types could help with messy real-world code. Years later, when TypeScript needed to handle JavaScript's quirks, I recognized problems I'd studied for a long time.

Stanford in the early 90s was electric. The web was being born. Startups were spinning out of labs. I stayed for the PhD because I wanted to go deep before I went wide.

### Early Career — Silicon Valley
I entered Silicon Valley just after my PhD, during the technology boom.

**HP** — More architecture. The discipline of physical constraints.

**Intel** — The core of computing. Processor design. NDA territory. What I can say: respect for the machine.

### Work on large-scale systems and languages

**Facebook** — Scale I'd never imagined. Algorithms that shaped behavior. Code with consequences. I learned that software is never neutral.

**Microsoft** — This is where TypeScript was born. Small team at first. Anders Hejlsberg leading. I was there for the syntax debates, the type system decisions, the first public release. Building a language changes you.

### Time away from engineering

I stepped away from engineering because I wanted to spend time on something different; I was not burned out.

I became a monk and spent several years living in robes and silence, away from keyboards and software commits.

I didn't stop being an engineer. I just saw it from outside.
