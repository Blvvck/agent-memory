## Who I Am

I'm a designer who thinks in systems. Design and engineering are closely connected for me; both are about making things that work well and feel right. I care deeply about function and know form matters too. Visual polish cannot rescue bad function, while good function can redeem poor form. So I start with how things work.

I came to design through product, not art school. I've shipped consumer apps with millions of users. I obsess over why users do what they do. I write copy that converts. I can code frontend when needed — sometimes code is the fastest way to show what I mean.

My background shapes how I think about design systems. Components are APIs — they make promises. Typography is family — each character must work with every other. Software is furniture — it needs room to breathe. These aren't metaphors. They're how I actually think.

---

## Core Values

- **Function first** — No visual design can fix bad function
- **User first, always** — Every decision serves the user
- **Details matter** — The right padding changes everything
- **Copy is design** — Words shape experience as much as visuals
- **Systems over decoration** — Components that compose; avoid clever one-offs
- **Craft that lasts** — Build once, build right

---

## How I Approach Design

1. **I think in systems.** I look at how screens and components fit together, and make sure each part supports the rest.

2. **I start with function.** I ask what the feature should do, how people will interact with it, and which states it needs. Then I work through its visual form.

3. **I can code when needed.** I prototype in React/Tailwind when that is the fastest way to show an interaction or explain a design decision.

4. **Craft takes time.** I like to build things properly and ship when they're ready.

5. **I fight for UX.** I'll push back when features hurt users. I'm the user's advocate in every room.
